‏================================================================================
‏راهنمای جامع نصب GeoRoute Manager روی سرور آپاچی (Apache) دارای سابقه وردپرس و cPanel
‏================================================================================
‏نسخه راهنما: 3.0 (سازگار با Apache 2.4، سرورهای قدیمی وردپرس، مسیر فرعی و cPanel)
‏توجه: این فایل با فرمت UTF-8 و چیدمان راست‌به‌چپ (RTL) فارسی تهیه شده است.
‏در ویرایشگرهای متن جهت نمایش را روی راست‌به‌چپ قرار دهید.

‏--------------------------------------------------------------------------------
‏بخش ۱: چرا نیازی به سرور جدید یا حذف آپاچی نیست؟
‏--------------------------------------------------------------------------------
‏وقتی قبلاً روی سرور شما وردپرس نصب بوده، وب‌سرور آپاچی (Apache2 / httpd) روی
‏پورت‌های ۸۰ و ۴۴۳ گوش می‌دهد. برنامه GeoRoute Manager اکنون به گونه‌ای اصلاح
‏شده است که:
‏  ۱. سرویس داخلی Node.js روی پورت داخلی `127.0.0.1:3000` اجرا می‌شود و هیچ
‏     تداخلی با پورت ۸۰/۴۴۳ آپاچی یا پایگاه‌داده MySQL وردپرس ایجاد نمی‌کند.
‏  ۲. فایل‌های `.htaccess` امنیتی در ریشه پروژه و پوشه `dist/` اضافه شده‌اند تا
‏     اگر پروژه داخل پوشه وب‌روت قبلی (مثل `/var/www/html` یا `public_html`)
‏     قرار گرفت، فایل‌های دیتابیس و `.env` محافظت شوند و قواعد قدیمی وردپرس
‏     (`index.php`) مسیرهای برنامه را خراب نکنند.
‏  ۳. امکان اجرا هم روی دامنه/زیردامنه مجزا (`panel.example.com`) و هم روی یک
‏     مسیر فرعی در کنار وردپرس (`example.com/georoute/`) با `BASE_PATH` وجود دارد.

‏پیش‌نیاز فنی حیاتی:
‏  - نسخه Node.js برابر با 22.13 یا جدیدتر (برای ماژول داخلی `node:sqlite`).
‏  - در سرور لینوکس با آپاچی، ماژول‌های `proxy`, `proxy_http`, `headers`, `rewrite`, `ssl`.

‏--------------------------------------------------------------------------------
‏بخش ۳: نصب روی سرور لینوکس دارای Apache (که قبلاً وردپرس داشته است)
‏--------------------------------------------------------------------------------

‏روش سریع (اسکریپت خودکار آماده در پروژه):
‏اگر از Ubuntu یا Debian با Apache2 استفاده می‌کنید و می‌خواهید پنل را روی یک
‏دامنه یا زیردامنه (مثلاً `panel.example.com`) بالا بیاورید:
sudo bash deploy/apache/setup-apache-ubuntu.sh panel.example.com
sudo certbot --apache -d panel.example.com

‏--- یا انجام دستی گام‌به‌گام برای تسلط کامل: ---

‏گام ۱ — نصب Node.js 22 LTS (بدون دست‌کاری Apache یا PHP/MySQL موجود):
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt update && sudo apt install -y nodejs openssl
node -v
‏(خروجی باید v22.x باشد.)

‏گام ۲ — آماده‌سازی مسیر پروژه (بهتر است خارج از پوشه قدیمی وردپرس باشد):
sudo mkdir -p /opt/georoute-manager
‏فایل‌های پروژه را در `/opt/georoute-manager` قرار دهید، سپس:
cd /opt/georoute-manager
npm install
npm run build

‏گام ۳ — پاک‌سازی یا محافظت از فایل‌های قدیمی وردپرس (اگر جایگزین کامل می‌کنید):
‏اگر می‌خواهید روی همان دامنه اصلی که قبلاً وردپرس داشته اجرا کنید:
‏  الف) از فایل‌های قدیمی `/var/www/html` و دیتابیس MySQL بکاپ بگیرید.
‏  ب) اگر فایل `.htaccess` قدیمی وردپرس هنوز در `/var/www/html/.htaccess` هست،
‏       حاوی `RewriteRule . /index.php [L]` است که تمام آدرس‌ها را می‌دزدد!
‏       در حالت VirtualHost Reverse Proxy (گام ۵) دیگر از `/var/www/html`
‏       استفاده نمی‌شود و ترافیک مستقیماً به Node.js روی `127.0.0.1:3000` می‌رود.

‏گام ۴ — ساخت فایل `.env` برای اجرا پشت Apache:
openssl rand -hex 32
openssl rand -hex 32

cat <<'EOF' > /opt/georoute-manager/.env
NODE_ENV=production
HOST=127.0.0.1
PORT=3000
BASE_PATH=
TRUST_PROXY=1
DATABASE_PATH=./data/georoute.db
SESSION_SECRET=کلید_اول_64_کاراکتری
CREDENTIAL_ENCRYPTION_KEY=کلید_دوم_64_کاراکتری
DIAGNOSTICS_LOCATION=Apache-Linux-Server
EOF

chmod 600 /opt/georoute-manager/.env
mkdir -p /opt/georoute-manager/data

‏گام ۵ — راه‌اندازی سرویس پس‌زمینه systemd:
sudo cp /opt/georoute-manager/deploy/apache/georoute.service /etc/systemd/system/georoute.service
sudo chown -R www-data:www-data /opt/georoute-manager
sudo systemctl daemon-reload
sudo systemctl enable --now georoute
sudo systemctl status georoute

‏گام ۶ — فعال‌سازی ماژول‌های Proxy آپاچی و تنظیم VirtualHost:
sudo a2enmod proxy proxy_http headers rewrite ssl

‏الف) حالت جایگزینی کامل وردپرس (روی دامنه اصلی یا زیردامنه):
sudo cp /opt/georoute-manager/deploy/apache/georoute-vhost.conf /etc/apache2/sites-available/georoute.conf
‏فایل `/etc/apache2/sites-available/georoute.conf` را ویرایش کرده و دامنه واقعی خود را
‏جایگزین `panel.example.com` کنید. اگر VirtualHost قدیمی وردپرس روی همین دامنه
‏فعال است، ابتدا آن را غیرفعال کنید (مثلاً `sudo a2dissite wordpress.conf`).
sudo a2ensite georoute.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
sudo certbot --apache -d panel.example.com

‏ب) حالت نصب در کنار وردپرس روی مسیر فرعی (`https://example.com/georoute/`):
‏۱. در `/opt/georoute-manager/.env` مقدار `BASE_PATH=/georoute` را تنظیم کرده و
‏   سرویس را ریستارت کنید (`sudo systemctl restart georoute`).
‏۲. محتوای فایل `deploy/apache/georoute-subpath-wordpress.conf` را داخل
‏   بلوک `<VirtualHost *:80>` و `<VirtualHost *:443>` فعلی سایت وردپرسی اضافه کنید.
‏۳. در فایل `.htaccess` وردپرس (قبل از `RewriteRule . /index.php [L]`) حتماً خط
‏   زیر را اضافه کنید تا وردپرس آدرس `/georoute` را به ۴۰۴ نبرد:
   RewriteCond %{REQUEST_URI} !^/georoute
‏۴. آپاچی را Reload کنید:
   sudo apache2ctl configtest && sudo systemctl reload apache2

‏--------------------------------------------------------------------------------
‏بخش ۴: نصب در هاست اشتراکی cPanel (آپاچی + وردپرس قبلی)
‏--------------------------------------------------------------------------------
‏بسیاری از سرورهای دارای cPanel نیز از وب‌سرور Apache (یا LiteSpeed سازگار با
‏`.htaccess`) استفاده می‌کنند.

‏۱. در کامپیوتر شخصی بیلد بگیرید:
npm install
npm run build
‏(این دستور پوشه `dist/` را همراه با `dist/.htaccess` جدید می‌سازد تا قوانین
‏ قدیمی وردپرس را خنثی کند.)

‏۲. فایل‌های قدیمی وردپرس در `public_html` را پاک یا به پوشه بکاپ منتقل کنید
‏   تا فایل `.htaccess` قدیمی وردپرس و `index.php` باقی نمانند.

‏۳. یک زیپ از پروژه (شامل `package.json`، `app.cjs`، `dist/`، `dist-server/` و بدون `node_modules`، `data` و `.env`)
‏   بسازید و **حتماً** در مسیر `/home/USERNAME/georoute-manager` (خارج از `public_html`) اکسترکت کنید.
‏   نکته مهم: در cPanel وارد کردن `public_html` در فیلد `Application root` مجاز نیست
‏   (`Directory "public_html" not allowed`). فایل‌های پروژه باید در پوشه‌ای مثل
‏   `georoute-manager` باشند، اما سایت همچنان روی ریشه اصلی دامنه بالا می‌آید!
‏   پوشه `public_html` را خالی بگذارید و فایل `.htaccess` خودکاری که cPanel داخل
‏   `public_html` می‌سازد را پاک یا جایگزین نکنید.

‏۴. در بخش **Setup Node.js App** در cPanel:
‏   - Node.js version: حتماً `22.x` یا `24.x` را انتخاب کنید.
‏   - Application mode: `Production`
‏   - Application root: `georoute-manager` (هرگز `public_html` ننویسید!)
‏   - Application URL: دامنه اصلی (`example.com`) را انتخاب کنید و کادر مسیر کناری را **خالی** بگذارید تا برنامه مستقیماً روی ریشه سایت باز شود.
‏   - Application startup file: `app.cjs`
‏   - متغیرهای محیطی `NODE_ENV=production`، `TRUST_PROXY=1`، `DATABASE_PATH=./data/georoute.db`،
‏     `SESSION_SECRET` و `CREDENTIAL_ENCRYPTION_KEY` را وارد کرده و `SAVE` را بزنید.
‏   - دکمه `Run NPM Install` (یا در Terminal دستور `npm install --omit=dev`) و سپس
‏     `Restart` را بزنید.

‏هشدار مهم برای هاست‌های آپاچی فقط-PHP (بدون Node.js 22):
‏  اگر سرور اشتراکی شما هیچ پشتیبانی از Node.js 22 ندارد و فقط Apache + PHP
‏  ارائه می‌دهد، امکان اجرای سرور Node.js روی آن هاست اشتراکی وجود ندارد
‏  (مگر اینکه دسترسی SSH/Root برای نصب Node.js 22 و اجرای گام‌های بخش ۳ را داشته
‏  باشید).

‏--------------------------------------------------------------------------------
‏بخش ۵: عیب‌یابی رایج در Apache
‏--------------------------------------------------------------------------------
‏۱. خطای 502 Proxy Error در آپاچی:
‏   مطمئن شوید سرویس `georoute` فعال است (`sudo systemctl status georoute`) و
‏   روی `127.0.0.1:3000` گوش می‌دهد. اگر SELinux فعال است (در CentOS/AlmaLinux):
   sudo setsebool -P httpd_can_network_connect 1

‏۲. نمایش صفحه «Not Found» یا خطای وردپرس هنگام رفرش صفحات:
‏   نشان‌دهنده باقی‌ماندن `.htaccess` قدیمی وردپرس یا عدم حذف `RewriteRule . /index.php`
‏   است. خط `RewriteCond %{REQUEST_URI} !^/georoute` را اضافه کنید یا VirtualHost
‏   را طبق بخش ۳ جایگزین نمایید.

‏۳. مشکل ورود به پنل روی HTTPS (کوکی نشست ذخیره نمی‌شود):
‏   مطمئن شوید ماژول `headers` فعال است (`sudo a2enmod headers`) و در VirtualHost
‏   SSL آپاچی خط `RequestHeader set X-Forwarded-Proto "https"` تنظیم شده است.
